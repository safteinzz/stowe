# AGENTS.md

## Hard rules
- Linux-first; Windows deliberately unsupported until it can be tested on Windows.

## Invariants and gotchas
- Remote availability: **existing folder proves nothing**, because unmounting leaves mountpoint dir behind, so bare dir check can target wrong disk. Proof: remote's on-disk `.stowe/` marker plus local record of where it is (`.stowe/remotes/<name>`). Known remote whose marker is gone errors, never recreated.
- `--mount`: script runs every time and is the authority; stowe trusts its exit code, never a folder. Scripts must be idempotent (instant no-op when already mounted). After success stowe still refuses path on root filesystem (`remote::on_local_disk`), best effort only: marker check is the guarantee.
- Remote record (`.stowe/remotes/<name>`): commit remote was last known at. Written by push and pull, cleared by `remote add` when location changes, set from remote's own `refs/main` whenever local remote is read (`remote::refresh_head` in `verify_reachable`; `remote add` and iremote's probe via `remote::read_head`). Foreign commit recorded too, so remote reads `diverged`. iremote's probe only reads; `App::reach_in` writes on main thread, drops probe older than last config change (`probe_seq`), writes nothing while job runs, since push records its own head as it ends. `status`, `repos`, `irepos` stay offline, read only record; s3 remote's record written only by push and pull. `mirror::drift` writes nothing, so detects case-folding filesystem by finding `.stowe` as `.STOWE`, not by probe file.
- Mirror sync plans against mirror's *actual* files, not only its manifest, else it can't repair drive someone deleted or corrupted files on.
- Drift judged against commit being *pushed*, not just recorded snapshot, else adapt → commit → push dead-ends on file just adopted.
- `.stoweignore` (`src/ignore.rs`) applies to working tree *and* every mirror walk (`mirror_sizes`, `adapt`), because phone regenerates `.thumbnails/` constantly, so junk ignored locally but not remotely reads as drift and demands `--force` every push. Explicitly named path (`stowe add junk.tmp`) still staged and stays visible to every later walk: mirror walk builds its `Ignore` `keeping` tracked paths, working-tree walk keeps whatever HEAD or index holds (`scan::holds`).
- Mirror filesystem may ignore case (exFAT, phone storage): case-only rename does nothing, copy onto case variant rewrites file under old name. So move onto name mirror already holds parks in `.stowe/tmp/` and lands after removals, folders respelled whole, two committed names differing only in case refused before push. `names::rename_unportable` picks safe names ignoring case and refuses one that would clash, since pre-push check already ran by then.
- Any write of file from remote: bytes checked against hash on the way (`scan::copy_verified`), because same-size edit on mirror is not drift and would otherwise come back as old version.
- `status` never decodes audio; only `add` fingerprints, since decoding dominates import cost.
- Which scan reads what: `scan::working` (status, istatus) leaves `hash` empty on every file whose bytes don't decide diff, so its tree stays inside `Working` and is only diffed. `scan::changes` (status -s, --prompt, repos, irepos) counts what `working` would, cached in `.stowe/cache/changes`. `scan::locate` (push) and `scan::Hashes` (pull, adapt) read only files they need; only `scan::scan` (add) hashes everything.
- Caches: every scan reuses hashes from HEAD, index and `.stowe/cache/hashes`; only `working` writes that cache (trusted per `HashCache::holds`). `Repo::snapshot` keeps commit's files in `.stowe/cache/head`, since big commit's JSON parses several times slower. Anything under `.stowe/cache/` may be deleted any time; nothing may fail over it.
- `status --prompt` starts hidden `status --refresh` detached with null stdio, because prompt reads command's output until every holder closes it. Prints refresh's answer if its scan `began` after prompt asked and lands within `PROMPT_WAIT`, else last line with ` …`. Refresh holds `prompt.run` lock while scanning, takes `prompt.wait` to queue behind one, leaves when another already waits, so slow disk never piles scans. `File::lock` is why `rust-version` is 1.89.
- Walking history for hashes only (`repos::hashes`): `Repo::read_parent`, never whole commit, since each commit holds whole snapshot.
- Walk's ignore check: `Walker::read` + `Ignore::walking` must answer exactly what `is_ignored` would on `Ignore` `keeping` tracked paths; walk never enters ignored folder, so `walking` meets each name once and is told whether folder above was named.
- Tree walk: keep `read_dir` + `DirEntry::metadata` (dirfd-relative stat; full-path stat far slower on deep FUSE trees). Working-tree walk reads folders in parallel, except on FUSE (`scan::on_fuse`), where one daemon serializes every stat, so parallel is *slower*. Results path-sorted; `line_up` and `diff`'s one-pass merge rely on it. Mirror walks stay sequential.
- Writing to mirror: names legal on ext4 can be unstorable on exFAT/NTFS (control chars etc.); push probes target FS empirically and offers rename fix. Never let raw `os error 22` reach user.
- tokio quarantined in object-store remote code; rest of program synchronous by design.
- Staging: every path that writes index (`add::stage_all`, `add::stage_paths`) calls `kept::keep` first, so small text file (≤1 MB, UTF-8, no NUL) gets copy in `.stowe/objects/<2>/<rest>`; istatus diffs only against these. Text committed before copies were kept has none, and pane says so.
- File IO and errors: call `fs_err::`, never `std::fs::`, so failure names file and operation. Show every error through `errors::words` (`io::Error` alone through `errors::io_words`), never `{e}` or `{e:#}`, because that turns OS error into words instead of `Permission denied (os error 13)`. `main` prints CLI errors through it; symphonia gets plain file from `fs_err::File::into_file`.
- Entry mtime: whole seconds; recorded through `scan::recorded_mtime`, which gives file stat'd in its own write second `model::UNTRUSTED_MTIME`, so same-size edit later that second is still hashed next scan. `.stowe/cache/hashes` keeps real mtimes instead, judged by `HashCache::holds`.
- TUI up: nothing may print. `scan::progress_to_screen` turns every `Progress` into footer line; every long operation has quiet core returning value (`push::push_one`, `adapt::adapt`, `convert::convert`, `restore::restore`, `add::stage_paths`, `unstage::unstage_paths`, `commit::commit`, `names::unstorable` + `names::rename_unportable`) under CLI `run` that prints it. New long operation gets same split, else its output lands on top of screen.
- Core that must stop with something to show fails with typed error caller downcasts, never `eprintln!`: `mirror::Drifted` (push or convert over drift), `mirror::Diverged` (push to remote at commit this repo lacks), `remote::Unseen` (push into empty local folder with no record and no mount command, which unmounted drive leaves too, so only `--force` writes there), `mirror::Conflicts` (adapt) carry what they found. CLI prints them; TUI turns drift and divergence into typed gate offering `--force`, unseen folder into plain gate that does, conflicts into alert. `app/jobs.rs`'s `Unportable` same for names drive can't store (TUI offers rename); its `Loses` stops adapt that would delete or overwrite files here (`mirror::plan_adapt`, then `apply_adapt` once typed gate answered, only while plan still loses exactly what gate listed). Mount command failure: `remote::MountFailed`, keeps end of stderr for alert since terminal it wrote to is covered again by then; cancelled one is status line.
- TUI touching remote with mount command: run it through `tui::suspended` (terminal handed over, SIGINT/SIGQUIT caught so Ctrl-C reaches only child, by one handler installed once and switched by flag, because unregistering signal-hook handler leaves signal ignored for good), then `remote::verify_reachable` from job's thread. Never `ensure_reachable` off main thread: it runs mount with terminal still taken.
- TUI key that writes config or index: ask `busy` in `app/keys.rs` first. Running job writes both as it ends (push records remote's head, stage writes index), so it would undo key's change. App never quits while job runs, since quitting kills job's thread mid-write.
- Drill reading history: `app/load.rs` walks it once per repo (`history::walk`) into `App::log`; commits pane, file's versions (`hist`) and scan's hits all derived from it. `hist` and `hits` hold indices into `log`, so `request_log` clears them with it, else index out of bounds when refresh lands.
- Restore gate: compare working file's size and mtime with HEAD's entry, as scan cache does; never hash on input loop (video would freeze screen). File unchanged since HEAD: plain gate when commit some remote is known at holds that version, typed gate when none does, since restore takes bytes only from remote. Uncommitted changes: typed gate. Missing file: no gate.
- `clone`: everything written before pull (folder, `.stowe/`, `origin` in config) taken back when remote turns out unreachable or empty, nothing once pull starts, since `stowe pull` in folder resumes partial clone. Local remote's format read off drive (`mirror::detect_format`), not assumed from scheme.
- Finding repos (`repos::find`): repo has `.stowe/HEAD`, mirror only `.stowe/refs/main`, so backup drive inside searched tree never listed as repo.
- Path display: remote URL through `paths::short_url` (what config holds, never resolved or canonical path), other paths through `paths::short`; `paths::expand` takes `~` back. So frame shows `~/drive`, never renderer's home or stage's absolute path.
- TUI keys: shared vocabulary is `tui-modeless.md`'s. Project's own: `K inspect` on every level; `a adapt`, `m mount`, `v convert` on iremote (`↵ push`); on istatus `↵ difftool` (editor when only one version of file is here), `s stage`, `u unstage`, `space flip`, `S`/`U` for every row on screen (scope and `/` decide which), diff scrolled with `ctrl-j/k`, panned with `ctrl-h/l`; `c create` makes commit there, remote on iremote; `↵ restore` on commit's changes. `d del` on istatus puts row back as HEAD has it behind typed gate (`status::discard`).

## The demo rig
- `stage.sh` builds fake home (invented media archive plus drive to back it up to). `shots.tape` and `shots-short.tape` render transcript stills, `plain.tape` plain twins' stills, one tape per interactive command (`history` / `status` / `remote` / `scan` / `repos`) its GIF, at 1056x664. Clips and `plain.tape` start from `./stage.sh story`: reorganisation committed and pushed, one more commit pushed, one not, work in progress, second archive (`Podcast`) for `irepos`. `status` and `remote` commit and push inside their stage, so each tape builds its own. `demo/render.sh` renders in container (image `demo/Dockerfile`), so machine needs only podman or docker: `./render.sh` runs every tape, `./render.sh <tape>` one, each in own container that stages, records, tears down, writing straight into `readme-assets/`.
- Two stills tapes because VHS fixes frame size per tape: `shots.tape` tall transcripts, `shots-short.tape` handful-of-lines ones; shot in wrong tape is mostly empty picture.
- `stage.sh` redirects `HOME` and every XDG variable into `demo/home` and sets `GIT_CEILING_DIRECTORIES` there, because stage sits inside this repo's working tree and without ceiling git-aware prompt reports *stowe's* branch and dirty count from inside media archive. Teardown unmounts everything under stage before deleting, because `--mount` remote can put real drive or phone under that path.
- Fixtures: invented artists and shoots, `s3://example-archive/...` (RFC 2606), audio synthesised by ffmpeg so fingerprint fingerprints real audio.
- Everything rig creates lives in `demo/home` (gitignored), `stowe` symlink and staged shell's rc included, so one guarded delete takes all.
- `ls -l` prints renderer's user and group, so mirror listings in tapes show names only.

## Overview
Layout:
- `src/main.rs`: clap `Cmd` enum, dispatch match, and `--help` command list, rendered here (`help_template`) so interactive verbs get own `Interactive (TUI):` group; name starting with `i` (but `init`) goes there.
- `src/commands/<verb>.rs`: one file per command, each exposing `run`.
- Top-level domain modules: `repo` (`.stowe/` on disk), `model` (commits, entries, manifests), `scan` (walking and fingerprinting tree), `mirror` (playable remotes), `remote` (locating remote, making it reachable), `names` (portability, rename fixes), `ignore` (`.stoweignore`), `audio` (fingerprinting), `paths` (how path is shown to person, `~` back to path), `diff` (which characters of rename changed), `prompt`, `time`, `selfcmd` (`stowe self`), `kept` (copies of small text files in `.stowe/objects/`), `errors` (error in words, OS errors included).
- `history` (what each commit changed, `walk`, name search, file's names across moves) and `repos` (finding repos under folder, each one's state) serve both plain `search`/`repos` and TUIs.
- `src/tui/`: primitives with no screen knowledge: `input` (key predicates, `Accel`), `widgets` (`key_footer`, `Query`, `Modal`, gates, `Form` with pick fields, scrollbars), `highlight` and `difffeed` (side-by-side diff, highlighted off input loop), `difftool` (handed two files with `--no-index`, since there is no git repo), `suspended` for handing terminal to mount command.
- `src/app/`: drill. One `App` with `Level` stack (`Repos` → `Commits` → `Files`, with `Remotes`, `Scan`, `Status` as start levels, `Scan` stepping into `Commits`); `irepos`, `ilog`, `iscan`, `istatus`, `iremote` only pick start level. One file per level (`repos`, `commits`, `remotes`, `scan`, `status`), `load` holds every background read, `patch` istatus's diff (`git diff`-shaped text from kept copies, so `tui::highlight` draws it unchanged), `jobs` threaded work and its boxes, `inspect` the `K` reader, `keys` one arm per level, `ui` one per level.

`stowe`: Rust CLI on crates.io, git for files git chokes on (music, photos, video, datasets). Content-addressed, linear history (one `main`, no branches, no content diffs). Remote is either **mirror** (real playable folders on drive/phone, bookkeeping hidden in `.stowe/` beside them) or **backup** (deduped blobs, e.g. S3). Local remotes default to mirror, s3 to backup; `--format` overrides, `convert` flips remote in place. AGPL-3.0-only.
